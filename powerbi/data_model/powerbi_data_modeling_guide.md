# Power BI Data Modeling Guide

For the final verified CSV workflow, use [powerbi_final_setup_guide.md](./powerbi_final_setup_guide.md). The guide documents current exports, exact column types, model relationships, date-table setup, and KPI validation.

## Recommended connection

Import the four versionable CSV outputs generated by:

```powershell
python -m src.powerbi_preparation
```

The outputs are `data/powerbi/orders.csv`, `products.csv`, `customers.csv`, and `dates.csv`. Rename their Power Query tables to `fact_orders`, `dim_products`, `dim_customers`, and `dim_dates`; the supplied DAX uses those table names.

## MongoDB and API alternatives

MongoDB access requires a reachable MongoDB deployment and credentials configured locally in `server/.env` or process environment variables. Never commit `.env` or embed a cluster endpoint, username, or password in report instructions. Power BI's MongoDB/ODBC availability depends on the connector or driver installed in the user's environment.

The Express API is optional. Its order endpoint is paginated and accepts a maximum `limit` of 500; the API is not a bulk export endpoint. See [api_reference.md](../../docs/api_reference.md) for routes, parameters, and response shapes.

## Model relationships

- `dim_customers[Customer_ID]` (1) -> `fact_orders[Customer_ID]` (*)
- `dim_products[Product_ID]` (1) -> `fact_orders[Product_ID]` (*)
- `dim_dates[Date_ISO]` (1) -> `fact_orders[Order_Date]` (*)

Set all relationships active, single-direction from dimensions to fact. Parse both date columns to Power BI Date type before creating the date relationship. The date dimension should be marked as the official date table on `Date_ISO`.
