# Power BI KPI Definition and Model Notes

## Scope
This document describes the actual KPIs used in the project and maps them to the real cleaned fact and dimension columns generated by the ETL pipeline.

## Source tables
- `fact_orders.csv` - transactional line-item fact table
- `dim_products.csv` - product attributes and category context
- `dim_customers.csv` - customer segmentation and geography context
- `dim_dates.csv` - calendar dimension used for time intelligence

## KPI definitions

### Sales
- Total Sales: `SUM(fact_orders[Net_Sales])`
  - Business meaning: realized revenue after cancellation/returned order logic is applied.
- Gross Merchandise Value (GMV): `SUM(fact_orders[Gross_Amount])`
  - Business meaning: total pre-discount or pre-return order value before final net realization.
- Gross Profit: `SUM(fact_orders[Gross_Profit])`
  - Business meaning: the ETL-computed realized contribution stored per order line.

### Orders
- Distinct Orders: `DISTINCTCOUNT(fact_orders[Order_ID])`
- Units Sold: sum `fact_orders[Quantity]` only for `Order_Status_Group` in `Delivered` or `Shipped`.
- Average Order Value (AOV): total `Net_Sales` for nonblank `Order_ID` values divided by the number of distinct nonblank `Order_ID` values. This includes zero-sales cancelled/returned orders in the denominator.

### Cancellation and fulfillment
- Cancelled Orders: `CALCULATE([Distinct Orders], fact_orders[Order_Status_Group] = "Cancelled")`
- Cancellation Rate: distinct cancelled orders divided by all distinct nonblank orders.
- Cancelled GMV: `CALCULATE(SUM(fact_orders[Gross_Amount]), fact_orders[Order_Status_Group] = "Cancelled")`
- Fulfilment Success: `CALCULATE([Distinct Orders], fact_orders[Order_Status_Group] IN {"Delivered","Shipped"})`

### Product performance
- Product Sales: `SUM(fact_orders[Net_Sales])` grouped by `Product_ID`
- Product Quantity: `SUM(fact_orders[Quantity])` grouped by `Product_ID`
- Category Sales: `SUM(fact_orders[Net_Sales])` grouped by `dim_products[Category]`

## Business rules
- Do not treat cancelled orders as realized sales. `Net_Sales` is zeroed in cancellation/return scenarios by the ETL workflow.
- Missing `Net_Sales` values are excluded by sum aggregations; they must not be silently replaced with zero.
- Use `Order_Status_Group` to classify operational states rather than assuming that every order line completed successfully.
- The fact table is at line-item grain. Unit totals must use the documented eligible status groups; order counts use distinct nonblank order IDs.
- Product and customer slices should be performed via dimension tables and their keys (`Product_ID`, `Customer_ID`), not by duplicating business logic in the report layer.

## Power BI guidance
- Load the exported CSV files from `data/cleaned/` or `data/powerbi/` into Power BI.
- Use `dim_dates[Date_ISO]` as the date table and mark it as the official date table.
- Build relationships as follows:
  - `dim_customers[Customer_ID]` -> `fact_orders[Customer_ID]`
  - `dim_products[Product_ID]` -> `fact_orders[Product_ID]`
  - `dim_dates[Date_ISO]` -> `fact_orders[Order_Date]`
- Keep additive metrics in the fact table and descriptive attributes in the dimensions.

## Implementation note
These KPIs are intentionally based on the actual cleaned schema used by the project so they remain aligned with the SQL analytics layer and the Streamlit dashboard.
